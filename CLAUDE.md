# CLAUDE.md — website (kyralabs.dev)

Standing instructions for Claude Code sessions in this repo. Owner: Mohammed Thalha (YamTee), Kyra Labs.

## What this is

The Kyra Labs studio site: a static **Astro** site (`src/pages/index.astro`, `src/pages/privacy.astro` → `dist/index.html`, `dist/privacy.html`). It's built on the Kyra Labs Material 3 Expressive library **@kyralabs/m3exp-web 1.7** (`@kyralabs/m3e-tokens`, `m3e-css`, `m3e-react`, `m3e-elements`, `^1.7.0` from npm). Library repo: kyra-labs/m3exp-web; this site is its ROADMAP **M4** "org site". The library's `DECISIONS.md` and `CLAUDE.md` define the design rules.

## Commands

pnpm 12.11.2 (`packageManager`), Node ≥ 22.12; `.nvmrc` is pinned to **24.21.0** (2026-10-15: on Node 24.22.0, Cloudflare Workers Builds' Corepack setup of pnpm 12 fails with "Cannot find module …/corepack/v1/pnpm/12.11.2/bin/pnpm.cjs" before install; 24.21.0 is the last version that built. Only bump it after a Workers build passes on the new version).

- `pnpm dev`, `pnpm build` → `dist/`. Both run `pnpm gen` first: the theme from `src/brand.mjs` and the icon subset from `src/icons.txt`, into `src/styles/generated/` (git-ignored).
- `pnpm lint:css` (stylelint, tokens only), `pnpm typecheck` (astro check), `pnpm check:js` (client-JS allowlist on `dist/`), `pnpm check:seo` (`scripts/check-seo.mjs` on `dist/`: titles ≤ 60 characters, descriptions 50–160, self canonicals, og:title = title, og:site_name "Kyra Labs", JSON-LD parses, exactly one WebSite node "Kyra Labs" on the home page and none elsewhere), `pnpm check:no-js` (every page with JavaScript off: all text visible; saves screenshots), `pnpm lighthouse` (accessibility and SEO must be 100, mobile + desktop; performance warns below 85).

## Rules (owner's brief; the JS rule was updated on 2026-10-15)

- **Client JS: enhancement only.** Two `client:only="react"` islands (the navigation bar, `src/islands/SectionNav.tsx`; the waitlist form, `src/islands/WaitlistForm.tsx`: the m3e-css outlined text field, the LoadingIndicator and a snackbar whose `@kyralabs/m3e-elements/snackbar-host.js` is imported on the first submit, never at load) plus one small deferred module, `src/scripts/enhance.ts` (the m3e press ripple + `html.js`), imported from `Base.astro`. All content, headings, links, meta and structured data stay in the server-rendered HTML; JS never creates or loads content; nothing render-blocking in `<head>`. Prefer CSS (scroll-driven animations) when it can do the job. `scripts/check-client-js.mjs` enforces the allowlist (islands, Astro runtime, one enhancement module ≤ 4 KB gzip, never in `<head>`) and fails on anything else.
- **Never hide content waiting for JS.** Any "hidden before animation" state is gated behind `html.js` (set by `enhance.ts`); the load entrance is transform-only so nothing is ever hidden. `pnpm check:no-js` proves the page is complete with JavaScript off. Animate transform/opacity only (no layout shift), use the `--m3e-sys-motion-*` spring tokens, and respect `prefers-reduced-motion`.
- **Layout: m3.material.io's expressive system** (since 2026-10-20, replacing "a pane per section"). Page on `surface`, content capped at `--m3e-sys-window-width-extra-large`. **Duos** (`.duo`): a text pane (`.pane--text`, `surface-container-low`) next to an **art pane** (`.pane--art` + `.art--primary|secondary|tertiary|neutral`: a colour role, Material shapes behind, a content card in front on `surface-container-lowest`); side by side from 840px, 8dp apart (`--_gap`), `extra-large(-increased)` corners, 56dp padding from expanded. **Blocks** (`.block`): sections straight on the page surface, text aligned with the panes' text. Cards are tonal (filled, no shadow, no hover lift); lists are M3 segmented lists (`.seg-list`); feature rows lead with a Material Symbol in a tonal circle. Type: hero h1 display large (≈93px from 1200px: display large + display small, as m3.material.io's 96px), section h2 display small/medium from expanded, body large for paragraphs, small labels (`.signal`) in on-surface-variant. **Shapes**: `src/components/Shape.astro` renders any of the 35 Material shapes (`@kyralabs/m3e-shapes`, a dev dependency) to a static SVG at build time; decorative, `aria-hidden`; they grow in on load and turn with scroll (scroll-driven, no JS).
- **Tokens only**: no hard-coded colours, sizes, durations, easings or radii in `src/styles/site.css`, only `var(--m3e-…)`. stylelint enforces it with the library's own plugin (`tools/lint/`). The only literals allowed are the M3 window-size-class breakpoints in media queries and `vw` page margins.
- **Keep exactly**: all copy, section order (hero, about, principles, Antecedent, Spenzia, Pingogram, M3 Expressive Web, developer, contact), URLs/anchors (`/privacy.html` stays `.html`), privacy text, SEO meta, canonical, JSON-LD, og-image, robots, sitemap, favicons/manifest, and the Antecedent, Pingogram, M3 Expressive Web and Kyra logos. Any deliberate change gets called out in the PR. **Site name**: the home page's `WebSite` node (`name` "Kyra Labs", `alternateName` "kyralabs.dev", `url` = the canonical) is what Google reads for the name above the result; it lives in `index.astro` only, never in `Base.astro`, and `pnpm check:seo` fails without it. Titles are brand first and short (home "Kyra Labs: Independent app studio", privacy "Privacy policy · Kyra Labs"), with og:title (and twitter:title on the home page) set to the same string. Search phrases go in naturally (titles, descriptions, headings, body, alt text, accurate JSON-LD), never as keyword lists in visible text, alt text or hidden elements (Google's keyword-stuffing policy); the meta keywords tag is kept for the owner but Google ignores it.
- **Products**: Antecedent (live), Spenzia (in development), **Pingogram** (an open-source Telegram client for Android, early beta; pingogram.kyralabs.dev, kyra-labs/pingogram-android) and **M3 Expressive Web** (the studio's open-source Material 3 Expressive library; m3e.kyralabs.dev, playground m3epg.kyralabs.dev, kyra-labs/m3exp-web, npm `@kyralabs/m3exp-web`). Pingogram's copy follows its repo's branding rule: "Telegram" only descriptively, never as the product's name, and the section says it isn't affiliated with Telegram. Their logos and banners in `public/assets/img/` are copies: `pingogram-logo(-dark).svg` from pingogram-website `public/press/`, `pingogram-banner-*.webp` from its `public/og/home.png`, `m3exp-web-logo.png` from m3exp-web `.github/assets/m3exp-logo.png`, `m3exp-web-banner-*.webp` from its `apps/site/src/assets/og-image.png` (the README banner and social preview have a grey frame baked in). Below-the-fold images are `loading="lazy"`: two eager logos added a request to Lighthouse's LCP graph (+78 ms simulated LCP).
- **Navigation**: the mobile navigation bar holds five destinations (M3 maximum). Destinations with `isWide` in `src/nav.ts` (Pingogram, M3 Expressive Web) appear only in the top app bar from 1200px; the scroll spy selects nothing over a section the bar doesn't list.
- **Theme**: Kyra red `#d84848`, `fidelity`, with core colours neutral + neutralVariant `#808080` (grey surfaces, text and outlines) and tertiary `#c8862a` (amber), light + dark by `prefers-color-scheme` (`src/brand.mjs`, palette C chosen by the owner on 2026-10-15). With `fidelity`, `neutralVariant` must be set too or secondary text and outlines stay red-tinted. Don't use tertiary-container for decorative badges. **Font**: Google Sans Flex from m3e-tokens. **Icons**: Material Symbols Rounded via `src/icons.txt`.
- **Don't change the library from here.** Write up library bugs for the owner instead of working around them silently.
- **Hosting**: Netlify serves the domain (behind Cloudflare's proxy). `netlify.toml` sets `pnpm build` / `dist`, and without it a merge publishes the repo root and the site 404s (that happened on 2026-10-13). The planned move is to Cloudflare Workers static assets: `wrangler.jsonc` (Worker `kyra-labs-website`, `html_handling: "none"` so `/privacy.html` isn't redirected, `previews: {}`) + `public/_redirects` (`/` → `index.html`). Keep both working. (Checked 2026-10-22: kyralabs.dev already answers with the Worker's headers, Workers' `cache-control` and empty 404 bodies, and no Netlify request id; the owner should confirm and update this line.) `public/_headers` sends `X-Robots-Tag: noindex` on the Worker's own `*.*.workers.dev` hosts only (production, preview aliases, version URLs; Cloudflare's documented rule), so they can't compete with kyralabs.dev in search; kyralabs.dev gets no such header. Keep that rule **first** in the file: Netlify's parser only knows path rules, reads the `https://…` line as a header, and would attach `noindex` to any path rule above it (on its own it is ignored with a build warning).
- **Workflow**: branch → draft PR → CI green → tick "CI green", mark ready, post a self-review comment. The owner merges, never Claude. Commits end with `Co-Authored-By: Claude …`. `gh` needs `export PATH="$PATH:/c/Program Files/GitHub CLI"`. Never touch `.hallmark/` or `.agents/`.

## Known gaps / follow-ups

- Mobile performance (simulated) ~86–91 because of the React runtime for the islands (~92 KB gzip on 1.1); observed LCP is ~0.3 s. A long or slow load entrance pushes observed LCP/Speed Index up (655 ms + stagger did: ~1.3–2.3 s), so keep it short.
- Library findings reported in #3: per-component m3e-css imports miss `focus-ring.css`/`state-layer.css`; the m3e-tokens README uses a non-existent typescale shorthand; `m3e-theme --out` doesn't create directories; nav items always use `aria-current="page"`. 1.5 added window-size tokens (`--m3e-sys-window-*`), but media queries still need the px values.
- No ROND token for fonts-rond.css (the roundness axis can only be set with a literal, which the tokens-only lint rejects).
- `REDESIGN-NOTES.md` describes the pre-Astro hand-written site and is out of date.
